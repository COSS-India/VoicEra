# Top-level dependencies for the rumik-oss-1 slot.
#
# Pinned to tts/orpheus's set, deliberately: that combination of vllm, torch and
# transformers is already built and running on the same box against a 3B model,
# so it is the one stack here with evidence behind it rather than a resolution
# nobody has tried.
#
# NOT YET A RESOLVED SET. tts/orpheus ships a constraints.txt holding its full
# transitive closure, which is what makes its builds reproducible, and that file
# can only be written by freezing a build that worked. Do that on the first
# successful build here:
#
#   docker compose ... run --rm --entrypoint "" tts pip freeze > constraints.txt
#
# then add `-c constraints.txt` to the Dockerfile's pip install.

# --- inference ----------------------------------------------------------------
# vllm brings its own torch, triton and the nvidia CUDA wheels, and pins its own
# transformers. This folder no longer pins 4.57.6: the vLLM path imports the
# checkpoint's CONFIG class but never its modeling code -- hf_overrides routes
# the model to vLLM's own Cohere2 implementation -- so the version coupling that
# pin existed for is gone. (trust_remote_code is still required to read a config
# carrying an auto_map at all; see vllm_backend.py.)
#
# The consequence is worth stating. RUMIK_ENGINE=transformers runs upstream's
# generate_audio, authored against 4.57.6. It is a reference path for comparing
# audio, not a serving path, and it is best-effort on transformers 5.x. If it
# breaks there, compare against the previous image instead -- the branch before
# this one builds it.
vllm==0.25.1
torch==2.11.0
transformers==5.14.1
soundfile==0.14.0          # libsndfile: the mp3/flac/opus response formats
numpy==2.3.5
